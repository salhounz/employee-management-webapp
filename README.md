# Employee Management Webapp

This project is a small Spring Boot demo application that shows how a browser-based employee page can be secured with Spring Security, rendered with Thymeleaf, handled through Spring MVC, persisted with Spring Data JPA and Hibernate, and stored in an in-memory H2 database; it is intentionally a learning/demo application rather than a production employee-management system, with one page for listing, adding, and deleting employees and a single in-memory demo account.

## Top Down Architecture

The project follows the request path from the user interface down to persistence:

```text
Browser
  |
Presentation layer       Thymeleaf HTML template
  |
Transport/Web layer      Spring MVC controller and HTTP routes
  |
Application/security     Authentication and request authorization
  |
Domain/model layer       Employee JPA entity
  |
Persistence layer        Spring Data repository and Hibernate ORM
  |
Database layer           H2 in-memory database
```

| Layer | Responsibility | Implementation in this project | Main location |
| --- | --- | --- | --- |
| Presentation/UI | Displays employee data and collects user input in the browser. | Thymeleaf renders the employee table, add form, delete forms, and logout form. | [`employees.html`](src/main/resources/templates/employees.html) |
| Transport/Web | Converts HTTP requests into application actions and responses into pages. | Spring MVC maps `GET /`, `GET /employees`, `POST /employees`, and `POST /employees/{id}/delete`. | [`EmployeeController.java`](src/main/java/com/codysalhounz/springboot/EmployeeController.java) |
| Application/security | Controls who can access the web application and how login/logout work. | Form login, logout, BCrypt password encoding, and one in-memory user: `demo` / `demo123`. | [`SecurityConfig.java`](src/main/java/com/codysalhounz/springboot/SecurityConfig.java) |
| Domain/model | Defines the data the application works with. | `Employee` contains an autogenerated ID, name, email, and department. | [`Employee.java`](src/main/java/com/codysalhounz/springboot/Employee.java) |
| Persistence | Provides database operations without hand-written SQL. | `JpaRepository<Employee, Long>` supplies basic find, save, and delete operations. | [`EmployeeRepository.java`](src/main/java/com/codysalhounz/springboot/EmployeeRepository.java) |
| ORM/database mapping | Maps Java objects to relational tables and manages schema interaction. | Spring Data JPA uses Hibernate as the JPA provider. | `spring-boot-starter-data-jpa` in [`pom.xml`](pom.xml) |
| Database | Stores data while the application is running. | H2 runs in memory; Hibernate creates and drops the schema for each run. | [`application.properties`](src/main/resources/application.properties) |

## Request flow

1. An unauthenticated browser request is intercepted by Spring Security and sent to the generated login page.
2. The user signs in with `demo` / `demo123`.
3. Spring MVC routes the request to [`EmployeeController`](src/main/java/com/codysalhounz/springboot/EmployeeController.java).
4. The controller uses [`EmployeeRepository`](src/main/java/com/codysalhounz/springboot/EmployeeRepository.java) to read or write employees.
5. Spring Data JPA and Hibernate translate repository operations into database operations against H2.
6. The controller places the result in the model and returns the `employees` view.
7. Thymeleaf renders the model as HTML for the browser.

## Startup and configuration

[`EmployeeManagementWebappApplication.java`](src/main/java/com/codysalhounz/springboot/EmployeeManagementWebappApplication.java) is the Spring Boot entry point. [`DemoDataConfig.java`](src/main/java/com/codysalhounz/springboot/DemoDataConfig.java) inserts Ada Lovelace and Grace Hopper when the database is empty.

The project targets Java 17 and uses Spring Boot 3.1.3. Dependencies, the Java version, and the Spring Boot Maven plugin are declared in [`pom.xml`](pom.xml). The project includes [`mvnw`](mvnw), the Unix-like Maven wrapper launcher, and [`mvnw.cmd`](mvnw.cmd), the Windows launcher. The wrapper scripts are standard Maven Wrapper 3.2.0 scripts, but this repository currently does not contain the expected `.mvn/wrapper` metadata, so a locally installed Maven command may be required until that wrapper directory is restored.

The current database settings:

- H2 URL: `jdbc:h2:mem:employees`
- Schema mode: `create-drop`
- SQL logging: enabled
- Thymeleaf template caching: disabled

## Running the application

With Java 17 and Maven available, run:

```text
mvn spring-boot:run
```

Then open `http://localhost:8080` and sign in with:

```text
Username: demo
Password: demo123
```

Because the database is in memory and uses `create-drop`, seeded and newly added employees are removed when the application stops.

## Testing

[`EmployeeManagementWebappApplicationTests.java`](src/test/java/com/codysalhounz/springboot/EmployeeManagementWebappApplicationTests.java) currently provides a Spring application-context smoke test through `@SpringBootTest`. It verifies that the application can assemble its configured components, but it does not test individual routes, authentication behavior, repository operations, or template rendering.
